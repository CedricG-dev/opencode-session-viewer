- (decision) Live-update transport: backend relays opencode's /event stream to the browser via Server-Sent Events (SSE / native EventSource), not WebSocket. Binds FR-3. Prevents: mixed WS/SSE reconnect logic across client code; rationale: FR-3 is one-way server->client only, SSE is the boring native-browser option with zero added dependency and structurally mirrors the opencode /event source it relays.
- (decision) Frontend stack: micro-framework (Preact/Solid + htm, no heavy JSX build pipeline) for the Dashboard UI, not a no-framework/vanilla-DOM approach. User's choice, anticipating the UI may grow toward deferred features (todo/diff-stats, per-model cost) in future versions.
- (decision) State ownership: backend holds the only authoritative session-state store (in-memory, rebuilt from client.session.list() at startup/reconnect, mutated only by event handlers). Frontend is a pure renderer of backend-sent state; it never derives or recomputes cost/status itself. Binds FR-2, FR-3, FR-4. Prevents: cost/status drift or duplicated computation logic between backend and frontend, directly protects the PRD constraint that Cost is never independently computed by the Plugin.
- (decision) Configuration (FR-5) is read from the plugin factory's second argument (options: PluginOptions), populated by opencode from the [name, options] tuple form in opencode.json's plugin array -- verified against @opencode-ai/plugin source (packages/plugin/src/index.ts, dev branch): 'export type Plugin = (input: PluginInput, options?: PluginOptions) => Promise<Hooks>'. Not client.config.get() (Config JSON schema has additionalProperties:false at top level, so a bare custom top-level key would not round-trip there).
- (version) Verified npm versions (2026-09-03): preact 10.29.8, @preact/signals 2.11.1.
- (constraint) opencode plugin factory signature confirmed: (input: PluginInput, options?: PluginOptions) => Promise<Hooks>. PluginInput = {client, project, directory, worktree, experimental_workspace, serverUrl, $}. Hooks relevant here: event (input:{event:Event}), config (input:Config), dispose(). Session events confirmed available: session.created/updated/idle/status/error/deleted/compacted/diff. Message events: message.updated/removed, message.part.updated/removed (no message.created).
- (decision) Frontend stack pinned: Preact 10.29.8 + @preact/signals 2.11.1 + htm (tagged-template, no JSX build step). Binds dashboard UI.
- (decision) Bundler: Bun.build (native, part of the Bun runtime the plugin already requires) builds the Preact/htm dashboard source into dist/ static assets served by the plugin's own HTTP server. No Vite/webpack dependency added.
- (decision) Wire format backend->browser over SSE: backend pushes its own derived per-session view model (id, title, status, tokens, cost, messageCount, lastActivity, errorFlag), never opencode's raw Event objects. Prevents: frontend re-deriving status/cost from raw events, which would violate the backend-owns-state invariant (AD state ownership) and couple the wire format to opencode SDK type churn.
- (decision) Dependency direction: core/ (session-state store / projector) must not import from server/ (HTTP/SSE) or dashboard/ (Preact). server/ and dashboard/ both depend on core/, never the reverse. Keeps state/derivation logic unit-testable without an HTTP server or a browser.
- (decision) Paradigm: Event-Sourced Projection + Reactive Push. opencode /event stream -> Projector (in-memory core/state-store.ts, pure update functions) -> SSE broadcast of the derived view model -> Preact+signals view (pure render, no client-side derivation).
- (decision) Package layout: single npm package (opencode-session-viewer) containing both the plugin backend (src/plugin.ts, src/core/, src/server/) and the dashboard frontend source (src/dashboard/), built to dist/ via Bun.build. No monorepo split -- matches the PRD's single npm-published plugin package requirement (Sec 9).
- (decision) SSE broadcast targets ALL currently-connected browser clients (no per-client filtering/auth). Acceptable given the single-user, single-project, localhost-only design (PRD Sec 5.1, Sec 8); multiple open dashboard tabs simply observe the same state.
